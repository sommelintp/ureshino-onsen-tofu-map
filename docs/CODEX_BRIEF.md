# Codex への依頼: 嬉野温泉 湯どうふマップ のビジュアル全面リデザイン

## 背景
- いまのサイトは機能は揃っているが、文字情報ばかりで写真も動画もなく、見た目が地味で魅力が伝わらない（オーナー評価「ダサい」）。
- 目的は **温泉湯どうふの魅力（とろける豆腐、湯気、白濁したスープ、温泉街の雰囲気）を写真と動画で伝え、行きたくさせる** こと。
- **情報・コンセプト・機能は今のまま**。変えるのは見た目・情報設計・写真/動画の見せ方だけ。

## ゴール（完成の定義）
1. 初めて開いた人が、最初の画面で「とろける温泉湯どうふ」が写真/動画で目に入り、食べたくなる。
2. 店を選ぶと、その店で実際に食べた人の Instagram / TikTok / YouTube 投稿が見られる（店名・場所が確実に分かる投稿のみ）。
3. 地図・一覧・絞り込み・詳細・投稿フォームなど既存機能はすべて動く。スマホ（幅390px）で快適。
4. 観光協会や市のサイトからリンクされても恥ずかしくない品質。

## 1. 写真・動画（SNS 埋め込み）の仕組みを追加する

### データ（バックエンドで用意済み）
- `data/media.json` と `TofuData.loadMedia()` があります（docs/ARCHITECTURE.md の Media）。いまは空なので、
  モックでは仮の投稿 URL を `docs/mockups/` 内のダミーデータとして使ってください（`data/media.json` には書かない）。
- 投稿フォームの「写真・動画の投稿URL」欄は `TofuData.issueUrl({ ..., media })` に `media` を渡せば Issue に入ります。
- **空でも見栄えが崩れないこと**（下記の写真なし表示）。

### 表示: 公式の埋め込みのみを使う（画像のダウンロード・転載は禁止）
- Instagram: 公式 embed（`blockquote.instagram-media` + `https://www.instagram.com/embed.js`）。
- TikTok: 公式 embed（`blockquote.tiktok-embed` + `https://www.tiktok.com/embed.js`）。
- YouTube: `youtube-nocookie.com/embed/<id>` の iframe（ショートも可）。
- 埋め込みスクリプトは **その投稿が画面に入ったときだけ遅延読み込み** する（IntersectionObserver）。59件分を一度に読まない。
- 埋め込みの読み込みに失敗したときは「Instagram で見る」などのリンクカードに切り替える。
- 投稿者へのリンクと元投稿へのリンクを必ず残す（埋め込みが自動で表示するもので可）。

### 配置
- **トップ（ヒーロー）**: 縦長動画/写真のカルーセル（TikTok・リール風）。「とろける瞬間」が伝わる投稿を優先表示。
  media が空のときは、後述のイラスト/グラデーションのヒーローに自動で切り替える。
- **店の詳細**: 名前の直下に、その店の投稿を横スクロールで表示。件数バッジ（📷 3）を一覧カードとピンにも出す。
- **一覧カード**: 投稿がある店はサムネイル風の帯（埋め込みの代わりに「投稿あり」の目印でよい。埋め込みは重いので一覧には出さない）。
- **絞り込み**: 「写真・動画あり」チップを追加。

### 投稿の集め方（サイトに導線を作る）
- 投稿フォーム（情報を追加・修正）に「Instagram / TikTok / YouTube の投稿URL」欄を追加する（送信は `TofuData.issueUrl`）。
- 掲載の確認ルール（店名が確実に分かる投稿だけ載せる等）はバックエンド側で運用する。

## 2. デザインの方向性
- テーマ: **「湯けむりと、とろける白」**。嬉野の温泉街・嬉野茶の緑・土鍋の焦げ茶・豆腐の白・湯気。
  和の上品さ（老舗旅館のパンフレット）と、SNS 世代が保存したくなる写真主体のレイアウトの両立。
- 写真/動画が主役。テキストは短く、余白を広く。カード型・角丸を多用しすぎない（いまの「全部カード」をやめる）。
- タイポグラフィ: 見出しは明朝系（例: Shippori Mincho / Zen Old Mincho）、本文はゴシック（Noto Sans JP / Zen Kaku Gothic New）。
  価格は大きく、数字は等幅（tabular-nums）。
- 色: 背景は温かい白（和紙）、アクセントは嬉野茶の深緑、差し色に土鍋の茶。ダークモードも用意。
- ヒーロー: 全画面の縦動画/写真 + 大きなコピー「湯けむりの中で、とろける。」+「近くの湯どうふを探す」ボタン。
- 地図: Google マップのスタイルを落ち着いた配色にする（`config.js` の `GOOGLE_MAPS_MAP_ID` に Cloud 側のスタイルを当てる想定。
  コード側では Map ID 未設定時に `styles` 配列で淡い配色にしてもよい）。ピンは豆腐/湯気モチーフのカスタムマーカー。
- モバイル: 下部固定のタブ（さがす / 地図 / 写真 / 投稿）、詳細はボトムシート。親指で操作しやすい位置にボタン。
- 既存のイラスト（`js/illust.js`）は使っても置き換えてもよい。
- 「温泉湯どうふとは」はモーダルではなく、トップを下にスクロールすると読める読み物セクション（とろける理由・発祥・泉質）にする。

## 3. 情報設計（ページ構成の提案。改善してよい）
1. ヒーロー（動画/写真 + コピー + 「近くで食べる」「地図で見る」）
2. 目的別の入口: 「ランチで食べる」「旅館で泊まって食べる」「お土産に買う」「日帰り温泉と一緒に」（既存の提供形態・種別フィルタにつなぐ）
3. みんなの写真・動画（media 一覧のグリッド）
4. 地図＋一覧（既存機能）
5. 温泉湯どうふとは（`data/background.json`）
6. 豆腐の製造元を食べ比べ（tofu_maker の店と、その豆腐を使う店の関係）
7. 情報提供のお願い（投稿フォームへ）

## 4. 技術条件
- `AGENTS.md` の「変えてはいけないもの」を守る。
- ビルド不要の静的サイトのまま。フレームワーク導入は不可（必要ならプレーンJSで）。
- 外部スクリプトは バージョン固定 + SRI。Instagram/TikTok の embed.js は SRI を付けられないので、必要になったときだけ動的に読み込む。
- パフォーマンス: 初回表示で読み込むのは地図とヒーローのみ。埋め込みは遅延。Lighthouse モバイル Performance 80 以上を目安。
- アクセシビリティ: 動画は自動再生しても無音・ループ、`prefers-reduced-motion` では静止。代替テキスト・キーボード操作。
- OGP 画像（`og-image.png`）も新デザインに合わせて作り直す。

## 5. 進め方
1. まずデザイン案（トップ・一覧・詳細・スマホ）を HTML のモックとして `docs/mockups/` に作り、スクリーンショットを PR に貼る。
2. オーナーの OK 後に本体へ適用。ブランチ `codex/redesign` で作業し、PR を出す（`main` へ直接 push しない）。
3. PR 説明に: 変更点、スクリーンショット（PC/スマホ・ライト/ダーク）、既存機能の動作確認チェックリスト。
