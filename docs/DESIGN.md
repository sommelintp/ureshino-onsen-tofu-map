# 嬉野温泉 湯どうふマップ — 設計書（ドラフト v0.1）

最終更新: 2026-10-04

## 1. 目的

嬉野市（嬉野町・塩田町）で名物「温泉湯どうふ」を **食べられる・買える場所** を 1 枚の地図に集約し、
一般の人が見られる形で公開する。嬉野温泉では、ほぼ全ての旅館・ホテル・料理屋・温泉施設が
温泉湯どうふを出しており、対象は数十〜百件規模になる。

集める情報:

- 店名・種別（飲食店 / 旅館・ホテル / 豆腐店・製造元 / 物販・土産 / 温泉施設 / その他）
- 住所・座標・電話・営業時間・定休日
- 温泉湯どうふ関連メニューの **バリエーションと価格**（定食・コース・朝食・日帰りプラン・通販セットなど）
- **どこの豆腐**を使っているか（自家製 / 製造元名）
- **どこの温泉（源泉）**を使っているか
- 特徴（発祥、創業年、とろけ方、タレ、テイクアウト可 など）
- 各サイトの URL（公式 / 食べログ / Retty / Google マップ / ぐるなび / ホットペッパー / じゃらん / 楽天トラベル / Instagram）
- **出典**（タイトル・URL・確認日・備考）
- 確信度（high / medium / low）と公開状態（公開 / 要確認 / 非公開）

## 2. 利用者と権限

| 役割 | 誰 | できること | 認証 |
| --- | --- | --- | --- |
| 閲覧者 | 一般の方・観光客 | 地図閲覧、検索、絞り込み、URL 共有 | 不要（公開サイト） |
| 投稿者 | 一般の方・お店の方 | 「情報を追加・修正」フォームから提案 | GitHub アカウント（Issue）または Google フォーム（任意） |
| 編集者 | 嬉野市職員・観光協会・旅館組合などの担当者 | スプレッドシートの直接編集、投稿の確認・採用、公開/非公開の切替 | Google アカウント（シート共有）※GitHub でも可 |
| 管理者 | リポジトリ所有者 | サイト設定、Pages、Actions、編集者の招待 | GitHub + Google |

- **編集者アカウントの共有** = Google スプレッドシートを「編集者」として共有するだけ。
  GitHub を使えない担当者でも編集できる。GitHub が使える担当者はリポジトリの collaborator として JSON を直接編集してもよい。
- **一般公開** = GitHub Pages（`https://<owner>.github.io/ureshino-onsen-tofu-map/`）。

## 3. 全体アーキテクチャ

```
 一般の方 ──閲覧──▶ GitHub Pages（静的サイト: index.html + js/ + css/ + data/）
                       │ 起動時に fetch
                       ├── 1) Google スプレッドシート（公開: リンクを知っている全員が閲覧可）
                       │      gviz CSV エンドポイントから最新データを取得
                       └── 2) 取得失敗時: data/places.json（リポジトリ同梱スナップショット）

 編集者 ──編集──▶ Google スプレッドシート「places」シート（正本）
                 「投稿（未確認）」シート（フォーム回答・Issue 転記）

 投稿者 ──提案──▶ GitHub Issue Form（.github/ISSUE_TEMPLATE/*.yml、サイトのフォームから事前入力）
                 または Google フォーム（任意、回答はシートに蓄積）

 GitHub Actions
   ├── pages.yml       main への push で Pages にデプロイ
   ├── validate.yml    PR/push 時に data/places.json をスキーマ検証
   └── sync-sheet.yml  毎日 1 回シート → data/places.json をスナップショット（差分があればコミット）
```

設計方針:

- **ビルド不要・依存ゼロ**の静的サイト（Leaflet を CDN から読み込み）。
  市の担当者が引き継いでも保守できるよう、フレームワークやビルドツールを使わない。
- **正本はスプレッドシート**、リポジトリの JSON は「スナップショット兼フォールバック」。
  シートが未設定・非公開・取得失敗でも、サイトは JSON で必ず動く。
- **出典のない情報は載せない**。価格には時点（確認日・年）を残す。未確認は「要確認」と明示して表示する。
- 住所から座標を自動取得する API はクラウド実行環境から使えないため、座標付与は
  ローカルで実行するスクリプト（国土地理院ジオコーダ）か、編集者が Google マップのリンク/座標を貼る運用にする。
  座標未確定の店は地図に「概略位置」として表示し、閲覧者が地図クリックで正しい位置を提案できる。

## 5. スプレッドシート設計（編集者が触る唯一の画面）

シート `places`。1 行 = 1 施設。列はすべて日本語見出し。複数値は **1 セル内で改行区切り**、
項目内の区切りは全角/半角どちらでも `|` を使う。

| 列 | 内容 | 例 |
| --- | --- | --- |
| id | 英数字スラッグ（空なら自動生成） | yokocho |

- 列の対応表（日本語見出し ⇄ JSON キー）は `js/schema.js` に一元化し、ブラウザと Node スクリプトの両方で使う。

## 6. 画面仕様

- **ヘッダー**: タイトル、件数、最終更新、「情報を追加・修正」ボタン、「温泉湯どうふとは」リンク。
- **絞り込み**: フリーワード（店名・メニュー・特徴・豆腐）、種別チップ、提供形態チップ、
  使用豆腐（製造元）セレクト、価格帯スライダー（メニュー最安値ベース）、「要確認を含む」トグル。
- **地図**: Leaflet + 地理院タイル（淡色）。種別ごとに色分けしたマーカー。座標「概略」は点線リング表示。
  地図移動で一覧を絞る「表示範囲で絞る」トグル。現在地ボタン。
- **一覧**: カード（名称・種別・最安メニューと価格・使用豆腐・確信度バッジ）。クリックで詳細。
- **詳細パネル**: 基本情報、メニュー表（品名 / 価格 / 備考 / 出典リンク）、使用豆腐（製造元へのリンク）、
  使用温泉、特徴タグ、説明、外部リンク一覧、出典一覧（確認日）、「この店の情報を修正する」「位置を修正する」。
- **投稿モーダル**: 入力 → GitHub Issue（事前入力 URL）/ Google フォーム（設定時）/ メール（設定時）。
  位置修正は地図クリックで座標を取得して本文に含める。
- **URL 共有**: `#place=<id>` で詳細を直接開く。フィルタ状態もハッシュに保持。
- **モバイル**: 地図/一覧の切替タブ、詳細はボトムシート。
- **アクセシビリティ**: キーボード操作、十分なコントラスト、`prefers-color-scheme` 対応。

## 7. 運用フロー

1. **初期投入**: 本リポジトリの `data/places.json`（Web リサーチで収集、出典付き）→ `npm run csv` で CSV 化 → シートへ。
2. **編集者**: シートを直接編集。即時にサイトへ反映（ブラウザがシートを読む）。
3. **一般投稿**: Issue または Google フォーム → 編集者が確認 → シートに転記 → 公開。
4. **スナップショット**: `sync-sheet.yml` が毎日シートを JSON 化してコミット（履歴が git に残る）。
5. **座標付与（ローカル）**: `npm run geocode` が座標未設定の行を国土地理院 API で補完（クラウド環境からは不可）。
6. **品質ルール**: 出典なしの情報は「要確認」止まり。価格は確認日を必ず残す。年 1 回は全件の価格・営業時間を見直す。

## 8. 公開手順（管理者）

1. GitHub → Settings → Pages → Build and deployment: **GitHub Actions**。
2. `main` に push すると `pages.yml` がデプロイ。URL は `https://<owner>.github.io/ureshino-onsen-tofu-map/`。
3. スプレッドシート: 共有 → 「リンクを知っている全員」= 閲覧者（サイトが読むため）。編集者は個別に「編集者」で追加。
4. `config.js` の `SHEET_ID` をシートの ID に設定。
5. （任意）Google フォームを作成し、`config.js` の `FORM_URL` に設定。
